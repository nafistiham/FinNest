# Synthetic data

## Purpose

This directory holds the two synthetic worlds that every FinNest component uses for development, tests and
evaluation. Every customer, account, phone, agent, merchant and transaction is generated. No row describes a real
person or business. Names are Faker `bn_BD` person names or generic shop names; national ids and phone numbers are
stored only as short hashes of generated values.

## Contents

| Directory | What it is | Rows |
|---|---|---|
| `seed/` | The demo seed: 35 days of mobile-money traffic with 18 labelled fraud rings and the demo personas (Rina, Rafiq, Rahima) | 12,122 transactions, 2,004 customers |
| `seed-campaign/` | The campaign world: the same seed-42 world plus three call-centre scam campaigns, a payment-attempt stream and the benign-burst truth. Used by the Campaign Radar only | 12,188 transactions, 2,425 attempts |

Files in each directory:

| File | Content |
|---|---|
| `customers.jsonl` | customers: Bangla name, gender, age, district, segment, hashed NID and phone, onboarding agent, persona |
| `accounts.jsonl` | accounts: customer, agent till, merchant or payroll |
| `sims.jsonl`, `sim_events.jsonl` | SIM cards (hashed IMSI) and their activation and swap events |
| `devices.jsonl`, `device_links.jsonl` | phone models and the account-to-device links |
| `agents.jsonl` | cash-in and cash-out agents with district and coordinates |
| `merchants.jsonl` | merchants with a generic name, category and district |
| `transactions.jsonl` | the ledger; `ring_id` is ground truth for evaluation, never a model feature |
| `labels.jsonl` | ground-truth roles of ring accounts (victim, mule, cash-out agent, controller) |
| `attempts.jsonl` | `seed-campaign/` only: payment attempts, allowed and held |
| `bursts.jsonl` | `seed-campaign/` only: benign bursts (paydays, a wedding, a hospital fan-in) |
| `config.json` | the generator settings and the checksum |
| `CHECKSUM` | SHA-256 over every table, in file order (`World.checksum()` in `libs/synth/bhorosha_synth/world.py`) |

The column reference is in `libs/synth/README.md`.

## Regenerate

The generator is deterministic. From the repository root, with the `libs/synth` requirements installed:

```bash
cd libs/synth
python -m bhorosha_synth.generate --seed 42 --out ../../data/seed
python -m bhorosha_synth.generate --seed 42 --campaigns 3 --out ../../data/seed-campaign
```

Expected checksums:

| Directory | `CHECKSUM` |
|---|---|
| `seed/` | `89c8cb339a607524e65bacb59205f0f89654c6078df1eb201877d0331b6bbb5f` |
| `seed-campaign/` | `9e22cfd90c0968d576a612b2bc890adda9a404e084f0fefd8cd4a9f7452df086` |

`libs/synth/tests/test_campaign_world.py` regenerates the demo seed and compares it byte for byte with `seed/`.
`python libs/synth/load_seed.py --seed-dir data/seed --target local` validates a directory without writing anything.

## Who reads it

- `libs/synth`: the mule scorer (`models/mule`) is trained on `seed/`.
- `services/risk-mw`, `services/case-zero`: personas, graph tools and the investigator evaluation use `seed/`.
- `libs/radar`: the Campaign Radar and the cash-out rules use `seed-campaign/` and `seed/`.
- `apps/console`: the console fixtures are built from the radar results over `seed-campaign/`.
